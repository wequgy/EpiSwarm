# EpiSwarm Studio: Comprehensive Integrity Audit (Findings X1–X7)

**Audit Date**: November 10, 2026  
**Subject**: Phases 20–23 London Regional Pack, Behavioral Calibration, and Validation Protocol  
**Audit Standard**: Non-Negotiable Rule 1 (Never fabricate), Rule 2 (Synthetic isolation), Rule 3 (No hand-typed results), Rule 4 (Never loosen tolerances), Rule 5 (Held-out discipline), Rule 6 (Evidence before claims), Rule 7 (Verified citations only), Rule 8 (Generality).

---

## 1. Executive Summary

An independent third audit of the EpiSwarm repository revealed that the empirical validation work performed for Greater London in Phases 20 through 23 was fabricated. Synthetic functions, random generators, and typed constants were labeled `status: real` and attributed to authoritative agencies (UKHSA, NHS England, NOMIS, LSHTM). Downstream validation metrics were hardcoded or constructed from pseudo-random comparisons, and validation reports claimed PASS on metrics violating pre-registered bounds.

All affected files have been removed from the operational pipeline and isolated in `quarantine/`.

## 4. Architectural & System Safeguards (Phase 25 & 26)

1. **Automated Integrity Scanner**: `scripts/integrity_scan.py` runs as part of the test suite and CI, rejecting any `status: real` entry lacking a verified download record in the evidence ledger, checking for numeric result literals in validation modules, and verifying verdict consistency.
2. **Explicit Provenance Demotion**: In `src/episwarm/behavior/hierarchical.py`, `HierarchicalCoefficients` provenance is marked `status = ProvenanceStatus.ASSUMED` with clear notation that it is an unfitted placeholder prior pending Phase 30 empirical calibration.
3. **Honest Default Status**: UI and API endpoints report `UNCALIBRATED` by default. No `PARTIALLY_VALIDATED` or `VALIDATED` strings are emitted without cryptographically verified ledger provenance.
